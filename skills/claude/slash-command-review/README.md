# slash-command-review

Claude Code スラッシュコマンド実装をベストプラクティスに照らして包括的にレビューし、A-F 評価と具体的な改善提案を提供するスキルです。

## 概要

このスキルは、Claude Code のスラッシュコマンドファイル（`.claude/commands/*.md`）を6つの観点から評価し、A-F 評価とスコアを算出します。メタデータ品質、引数処理、動的機能、セキュリティ、スコープ、スキル境界などのベストプラクティスに準拠しているかをチェックし、具体的な改善提案を提供します。

## インストール

### 前提条件

Claude Code CLI がインストールされている必要があります。

### マーケットプレースの追加

```bash
/plugin marketplace add naoto24kawa/claude-plugins
```

### プラグインのインストール

```bash
/plugin install claude@naoto24kawa-claude-plugins
```

## 主な機能

### 6つの評価観点

1. **Frontmatter 品質**: YAML 形式、description、argument-hint、model、allowed-tools、disable-model-invocation
2. **引数処理**: `$ARGUMENTS` vs `$1`/`$2`、検証、デフォルト値、必須/オプションの明確性
3. **動的機能**: `!` プレフィックス（Bash）、`@` プレフィックス（ファイル参照）、エラーハンドリング
4. **スコープと構造**: プロジェクト vs 個人、ネームスペース、単一責任原則
5. **スキル境界**: 適切な複雑さ、単一ファイル完結性、スキル変換の推奨
6. **セキュリティとベストプラクティス**: コマンドインジェクション防止、ファイルアクセス制限、入力検証

### A-F 評価システム

- **A（優秀）**: 90-100点 - すべてのベストプラクティスに準拠
- **B（良好）**: 70-89点 - ほとんどのベストプラクティスに準拠、軽微な改善点のみ
- **C（要改善）**: 50-69点 - いくつかの重要な問題あり
- **D（多くの問題）**: 30-49点 - 多数のベストプラクティス違反
- **F（不合格）**: 0-29点 - 致命的な問題あり、全面的な再作成を推奨

### 優先度別の改善提案

- 🔴 **Critical**: 即座に修正（セキュリティ問題、データ損失リスク）
- 🟠 **High**: 早急に修正（機能問題、エラー傾向パターン）
- 🟡 **Medium**: 推奨（ベストプラクティス違反、最適化の機会）
- 🟢 **Low**: オプション（スタイル改善、一貫性向上）

## 使用タイミング

このスキルは以下のような場合に使用します：

- スラッシュコマンドを新規作成した後の品質チェック
- 既存コマンドの改善点を特定したい
- ベストプラクティスに従っているか確認したい
- セキュリティ評価が必要な時
- `.claude/commands/` ディレクトリのコマンドをレビューしたい
- コマンド実装を標準と比較したい

## 使い方

### 基本的な使用方法

1. **スキルの呼び出し**
   ```
   「slash-command-review スキルを使って [コマンド名] をレビューしてください」
   ```

2. **対象コマンドの指定**
   - 特定のファイル: `.claude/commands/component.md`
   - ディレクトリ: `.claude/commands/` 内のすべてのコマンド
   - コマンド名: `/component` → `.claude/commands/component.md`

3. **レビュー結果の確認**
   - 総合評価（A-F グレード）
   - 観点別評価
   - 優先度別の改善提案
   - 具体的な修正例
   - 改善版のコマンドファイル（必要に応じて）

### レビューワークフロー

#### Step 1: 対象コマンドの特定

どのスラッシュコマンドファイルをレビューするか決定：

1. **ユーザーがファイルを指定**: 指定された `.claude/commands/*.md` ファイルをレビュー
2. **ユーザーがディレクトリを指定**: そのディレクトリ内のすべての `.md` ファイルをレビュー
3. **ユーザーが "すべてのコマンド" と言う**: `.claude/commands/**/*.md` に一致するすべてのファイルを検索
4. **ユーザーがコマンド名を提供**: 対応するファイルを検索（例: `/component` → `.claude/commands/component.md`）

#### Step 2: コマンド構造の解析

各コマンドファイルについて、以下を抽出して分析：

**Frontmatter（YAML）**:
- `description`: コマンドの目的
- `argument-hint`: 予期される引数パターン
- `model`: モデル選択（haiku/sonnet/opus）
- `allowed-tools`: ツール制限
- `disable-model-invocation`: 自動呼び出し防止

**コマンドボディ（Markdown）**:
- 引数の使用（`$ARGUMENTS`、`$1`、`$2` など）
- Bash 統合（`!` プレフィックスコマンド）
- ファイル参照（`@` プレフィックスパス）
- 指示とワークフローステップ

**ファイルの場所**:
- スコープ（`.claude/commands/` vs `~/.claude/commands/`）
- ネームスペース（サブディレクトリ）

#### Step 3: 6つの観点で評価

各観点について、`references/evaluation-criteria.md` の基準に基づいてグレード（A-F）を割り当てます。

**評価観点の詳細**:

1. **Frontmatter 品質**: YAML 形式の正確性、description の明確性、argument-hint の存在、適切な model 選択
2. **引数処理**: `$ARGUMENTS` vs `$1`/`$2` の正しい使用、検証、デフォルト値処理
3. **動的機能**: `!` プレフィックスの安全な使用、`@` プレフィックスの適切な使用、エラーハンドリング
4. **スコープと構造**: 適切なスコープ選択、ネームスペースの活用、単一責任原則
5. **スキル境界**: スラッシュコマンドに適した複雑さ、スキル変換の推奨
6. **セキュリティ**: コマンドインジェクション防止、ファイルアクセス制限、入力検証

#### Step 4: レビューレポートの生成

各コマンドファイルについて包括的なレビューレポートを作成：

**レポート構造**:
- **サマリー**: コマンド品質の概要と主要な発見事項
- **観点別グレード**: 各観点の評価（A-F）とステータス（✅ ⚠️ ❌）
- **総合グレード**: 全体評価
- **詳細分析**: 各観点の発見事項、問題、推奨事項
- **優先度別の改善**: Critical / High / Medium / Low
- **改善版**: 必要に応じて修正版のコマンドファイル
- **参考例**: `references/examples.md` からの類似パターン

#### Step 5: 比較分析（複数コマンド）

複数のコマンドをレビューする場合、比較サマリーを追加：

- グレード分布（A-F の数とリスト）
- 共通の問題点
- 観察されたベストプラクティス
- コマンドスイート全体への推奨事項

## ベストプラクティス

### セキュリティ

**❌ 避けるべき - コマンドインジェクション脆弱性:**
```markdown
!rm -rf $1
```

**✅ 推奨 - 入力検証とクォート:**
```markdown
引数を検証し、安全な操作のみを許可してください。
```

### 引数処理

**❌ 避けるべき - 引数の説明なし:**
```markdown
$1 を使用して処理を実行します。
```

**✅ 推奨 - 明確な説明と検証:**
```markdown
---
argument-hint: <component-name>
---

$ARGUMENTS は React コンポーネント名です。PascalCase で指定してください。
```

### 動的機能

**❌ 避けるべき - 長時間実行コマンド:**
```markdown
!npm install
```

**✅ 推奨 - 短時間のコマンドのみ:**
```markdown
!ls src/components
```

## 重要な注意事項

1. **参照ファイルを常に読む**: 正確なグレーディングと推奨事項のため、参照資料を確認
2. **具体的で実行可能**: 正確な行やパターンを指摘し、改善のための具体的なコード例を提供
3. **セキュリティを優先**: セキュリティ問題は即座にグレードを下げ、Critical 優先度
4. **コンテキストを考慮**: チームリポジトリのコマンドは個人コマンドとは異なる要件がある
5. **例を提供**: `references/examples.md` を使用して良いパターンを示し、改善前後を表示
6. **建設的**: 何が間違っているかだけでなく、どう改善するかに焦点を当てる
7. **ユーザーの意図を尊重**: コマンドが意図的にシンプルまたは最小限の場合、オプション機能の欠如でペナルティを科さない
8. **スキル変換を慎重に提案**: 複雑さが本当に必要な場合のみ、スキルへの変換を推奨
