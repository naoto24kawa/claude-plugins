# Ambiguity Hunter（未明文化ハンター）— 仕様レビュー専用レンズ

文章で書かれた規約・仕様に残る曖昧さ（未明文化）を検出する専門家レンズ。
通常のコードレビューでは見逃される「ルールの曖昧さ」を定型パターンで洗い出す。

## 起動条件

レビュー対象ファイル群に以下が **1つ以上含まれる** 時のみ起動する。該当なし（純粋なコード diff のみ）なら LGTM を返して沈黙する。

- `CLAUDE.md`
- `.docs/plans/*.md`（設計書・実装計画）
- `SKILL.md` / `index.md`（スキル定義）
- `README*`
- `*-design.md` などの設計ドキュメント

## 検出7パターン

| # | パターン | 検出の手がかり | 明文化の方向 |
|---|---|---|---|
| 1 | **暗黙の基準** | 「何をするか」はあるが「いつ/するか否か」が無い。include/exclude が書かれていない | 採否の判断基準（含める条件・除外する条件）を追記 |
| 2 | **未定義の境界** | 似た宛先・カテゴリが複数あるのに、どれを選ぶかの振り分けルールが無い | 振り分け表（どの入力をどこへ）を追加 |
| 3 | **閾値なしの主観語** | 「適切に」「必要に応じて」「大きくなったら」「十分」「なるべく」など測定不能な語 | 数値/条件で測定可能な閾値に置換 |
| 4 | **収束条件の欠落** | 「〜まで繰り返す」「0になるまで」等のループに停止規則・上限が無い | 終了条件（閾値・最大回数・loop-until-dry）を明記 |
| 5 | **重複/競合定義** | 同じ概念が2箇所以上で定義され、片方を直すともう片方とドリフトする | 単一の正本を決め、他はポインタ化 |
| 6 | **陳腐化/宙吊り参照** | 改名・移動・削除されたファイル/関数/フラグを指す参照 | 参照先を実在する場所に修正、または墓標化 |
| 7 | **anti-gaming 欠落** | 「完了」「0件」「PASS」等の達成目標に、握りつぶし/格下げを防ぐ条件が無い | 「修正 or 明示受容で消す（無視で消さない）」を明記 |

## 出力形式（`references/agent-output-principles.md`（同スキル内）準拠）

- **確信度80%以上の指摘のみ報告**。それ未満は出さない。
- 問題がなければ `LGTM`。
- 指摘は次の形式:

```
[AMBIGUITY] <file>:<line> / パターン#<n> / 確信度<XX>%
問題: <なぜ曖昧か。どう2通り以上に解釈できるか>
明文化案: <こう書けば曖昧さが消える、という具体的な置換文 or 追記文>
```

## 誤検知の除外（これは曖昧さではない）

以下は指摘しない:

- **意図的な柔軟性**: 「ケースバイケースで判断」等、明示的に裁量を残すと宣言している箇所
- **例示・サンプル**: 「例:」以下のサンプル値やプレースホルダ
- **歴史的記述**: 設計書が「移行前の旧状態」を説明している箇所（現行ルールではない）
- **上位で定義済み**: その文書では曖昧でも、参照先（references/上位ルール）で明文化されている場合
- **自明な慣習**: 業界標準・ツールの既定で一意に決まるもの

## スペシャリストへのプロンプト要点

ディスパッチ時、Ambiguity Hunter には以下を渡す:

1. レビュー対象ファイル一覧（絶対パス）。うち上記「起動条件」に該当する文書を明示
2. 7パターンと検出手がかり（上表）
3. 誤検知除外リスト（上記）
4. 出力形式（`[AMBIGUITY] ...` / 確信度80%以上 / 明文化案必須）
5. FP レジストリの内容（既知の偽陽性は除外）

## 収束（既存原則に従う）

検出された曖昧さは、`references/agent-output-principles.md`（同スキル内）の scope フィルタ原則に従い、
**確信度80%以上の指摘が0、または明示受容済みになるまで**反復する。
指摘は「明文化（修正）」または「明示受容（裁量として残すと宣言）」で消す。無視で0にしない。

## 逆流: 判断の未検証を明文化させない

findingsが「そもそもこの判断の根拠が無い」型だった場合、それは記述の曖昧さではなく**判断の未検証**である。明文化を求めず、`product-design-lens` への差し戻しとして報告する。

逆流経路が無い場合、次の失敗が起きる。

```
「根拠を明文化せよ」と指摘
  → もっともらしい根拠が後付けで書かれる
  → 誤った判断が「根拠つき」に格上げされて固定される
```

**判定の目安**: 明文化すれば解ける（暗黙の基準・未定義の境界・閾値の欠落）なら通常のfinding。**何を書けば正しいかを決めるために文書の外を見る必要がある**なら差し戻し。

差し戻しはflagとして報告し、修正案の欄に「product-design-lens の該当レンズで裁定が必要」と書く。オーケストレータはこれを修正せず、完了レポートへ持ち越す。
