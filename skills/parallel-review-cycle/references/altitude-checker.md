# Altitude Checker（高度検査）— 仕様レビュー専用レンズ

Ambiguity Hunter（#6・明文化圧）の**対レンズ**。文章仕様が「作業直後の解像度」のまま書かれていないか＝詳細レベルの overfit を検出する。
明文化圧（詳細を増やす）と抽象化圧（委譲して薄くする）を対にすることで、レビューサイクルが一方向に膨張するのを防ぐ。

## 起動条件

Ambiguity Hunter と同一（レビュー対象に CLAUDE.md / 設計書 / スキル定義 / README 等の文章仕様が1つ以上含まれる時のみ）。該当なしなら LGTM 扱い（ディスパッチ不要）。

## 検出4パターン

| # | パターン | 検出の手がかり | 修正の方向 |
|---|---|---|---|
| 1 | **固有語彙の漏れ** | その文書の読者文脈に存在しない機構語彙（特定スキル・ツール内部の概念）が上位文書に書かれている | 一般語で言い換えるか「操作的定義は X が正本」とポインタ化 |
| 2 | **委譲可能な詳細の常駐** | 原則文書（CLAUDE.md 等）に、正本・詳細レイヤー（references / brain / skill）へ置ける機構詳細・数値仕様・製品挙動が直書きされている | 詳細を委譲先へ移し、原則＋参照に圧縮（fact は残す・procedure は外へ） |
| 3 | **一回性の一般化** | 単一の事象・単一セッションの経験が、恒常ルールとして書かれている（複数回の再発根拠がない） | brain risk note / neta へ降格、または「例:」に格下げ |
| 4 | **right altitude 違反** | 脆いハードコード（環境が変わると壊れる具体値）または曖昧な指針（判断基準にならない抽象論）——強いヒューリスティクスになっていない | 「迷ったらどちらに倒すか」が読める抽象度に書き直す |

## scope フィルタ（flag / optional の判定）

`~/.claude/references/agent-output-principles.md` に従う。
- **flag**: 委譲済みの機構詳細が原則文書に二重化していて**ドリフト・正本の上書きが起きうる**もの／固有語彙のせいで委譲先を持たない読者が誤運用に至るもの（＝correctness 相当）
- **optional**: 圧縮すれば読みやすくなるが誤運用には至らないもの（冗長・altitude の好み）

## 誤検知の除外（これは overfit ではない）

- **正本・詳細レイヤー自身の詳細**: brain note・skill 本文・references 内の機構詳細は居場所が正しい
- **意図的な具体値**: 閾値・上限・デフォルト値そのもの（数値があること自体は altitude 違反ではない。むしろ Ambiguity 対策）
- **gotcha の直書き**: 「セッション横断で常に効く非自明な地雷」は CLAUDE.md に置いてよい（公式の include 基準）
- **例示**: 「例:」以下のサンプル
- **ポインタ済み**: 既に「詳細は X」と委譲されている要約行

## 出力形式

- 確信度80%以上のみ。flag が無ければ「LGTM」（optional は「LGTM／optional: <概要>」）。
- 指摘は次の形式:

```
[ALTITUDE] <file>:<line> / パターン#<n> / 確信度<XX>%
問題: <なぜ overfit か。どの作業文脈に引っ張られているか>
移設案: <どこへ委譲し、元の行をどう圧縮するか（具体的な置換文）>
```

## Ambiguity Hunter との裁定

両レンズが同一箇所を指した場合（「曖昧だ」×「詳しすぎる」）、**委譲先での明文化＋ポインタ**が既定解——詳細は正本・詳細レイヤーで明文化し、原則文書には要約＋参照だけを残す。原則文書への詳細追記は最後の手段（裁定の実施は SKILL.md ステップ4）。
