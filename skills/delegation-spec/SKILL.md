# Delegation Spec — 委任仕様テンプレ

司令塔が worker（Codex / Claude）へ渡す task spec の必須構成。worker は literal に実行し、曖昧さを意図で補完しない前提で書く。

## 必須7節

1. **背景** — 前提事実と実測済み事項。worker に再調査させない範囲を明示する
2. **実施内容（literal）** — ファイルパス・変更単位まで具体化。「〜の趣旨で」を使う場合は範囲を限定する
3. **スコープ外** — 触ってはいけないファイル・やってはいけない操作を列挙する
4. **検証（rubric）** — 下記チェックリストを満たすこと。結果は worker_done の body に実測値で含めさせる
5. **レビューサイクル** — 実施者（委譲先で完結）を明記。レンズ選定は brain `ref-work-archetypes-bcherny` の対応表、収束規律は standards `AI_FIRST.md` §3 の値で（スキル既定値を上書き）
6. **完了条件** — PR 作成まで。main へのマージは human-gate。PR 本文の要件（変更概要・検証結果・レビュー記録・実装担当識別子）
7. **制約** — 「指示と実態が矛盾したら止めて ask で報告」（MUST）＋裁量範囲と変更申告義務

## 検証節の事前チェックリスト（書く前に司令塔が確認する）

失敗パターンの正本は `~/.claude/references/verification-pitfalls.md`。

- [ ] 検証コマンドは**書く前に実行してベースラインを取った**か（「PASS するはず」を期待値にしない）
- [ ] probe に使う値（クラス名・文字列・パス）の**実在を確認した**か
- [ ] 負の検査（禁止語 0 件等）は**出現位置まで指定した**か（部分文字列の偽陽性——実例:「ッピ」probe が「マッピング」に命中）
- [ ] 検証コマンドに pipe・`&&` 連結・`|| true` を**含めていない**か（個々の exit code を確認する形か）
- [ ] 検証報告に**実測の範囲**（可視 / 存在 / 実行 / 動作のどこまで測ったか）を要求したか
- [ ] 独立検証は**情報源まで分けた**か（間接証拠でなく実体への直接照会を1本混ぜる——実例: ディレクトリ一覧で「未配布」と誤判定、ランタイム照会で覆った）
- [ ] worker の完了判定は worker_done の受領でなく**成果物の実体との突合**にしたか

## 委任開始時の司令塔側手順

1. rubric を `/goal` へ積む文面をユーザーに提案する（CLAUDE.md「完了ゲート」の既定）
2. dispatch 後は送信を到達と見なさず、**worker が動いていることを実測**してから待機に入る（terminal 出力・作業ツリーの実体）
3. worker_done 受領後、**ack する前に**完了ゲート（rubric 突合・負の検査・スコープ確認）を独立実施する
