# 成功指標ガイド

このガイドは、Honoバックエンドレビューの改善効果を測定するための指標を定義します。

---

## DDD 整合性メトリクス

### ドメインモデル品質

| 指標 | 測定方法 | 目標 |
|------|----------|------|
| Entity/VO 比率 | VO数 / Entity数 | ≥ 2.0 |
| 集約サイズ | 集約内Entity数の平均 | ≤ 5 |
| ドメインメソッド率 | ビジネスメソッド数 / 総メソッド数 | ≥ 0.7 |

### ユビキタス言語一致率

| 指標 | 測定方法 | 目標 |
|------|----------|------|
| 用語一致率 | ドメイン用語と一致するクラス名 / 総クラス数 | ≥ 0.9 |
| 技術用語混在率 | 技術用語を含むドメインクラス / 総ドメインクラス | ≤ 0.1 |

## 測定方法

### 自動測定

- **静的解析**: TypeScript AST解析で型定義、any使用を測定
- **テストカバレッジ**: vitest/jest でカバレッジ測定
- **Cloudflareメトリクス**: Workers Analytics API で取得

### 手動測定

- **ドメインモデル評価**: レビュー時に目視確認
- **ユビキタス言語一致**: ドメインエキスパートとの確認

## 改善目標の設定

### 短期（1-2週間）

- Critical問題の解消
- any使用の削減
- 基本的な型定義の追加

### 中期（1-2ヶ月）

- DDDパターンの適用
- イベント駆動の信頼性向上
- オブザーバビリティの改善

### 長期（3-6ヶ月）

- 全メトリクスの目標達成
- 継続的な改善プロセスの確立
