# Plan 分析基準

plan の内容を分析し、適切なワークフロータイプを判断するための基準。

## 分析観点

### 1. 変更の種類

| 種類 | 説明 | 推奨アクション |
|------|------|---------------|
| **feat** | 新機能追加 | Issue → 実装 → PR |
| **change** | 既存機能の変更 | Issue → 実装 → PR |
| **remove** | 機能削除 | Issue → 実装 → PR |
| **fix** | バグ修正 | 軽微: PR のみ / 重大: Issue → PR |
| **refactor** | リファクタリング | PR のみ |
| **docs** | ドキュメント | PR のみ |
| **chore** | 雑務 | PR のみ |

### 2. 実装状態

| 状態 | 判断基準 | 推奨アクション |
|------|---------|---------------|
| **未着手** | コード変更なし、plan のみ | Issue 作成から開始 |
| **実装中** | 一部コード変更あり、未完了 | 状況に応じて Issue/PR |
| **実装完了** | 全変更コミット済み、テスト通過 | PR 作成 |

### 3. 仕様の明確さ

| 状態 | 判断基準 | 推奨アクション |
|------|---------|---------------|
| **明確** | As-Is/To-Be が定義済み | そのまま進行 |
| **曖昧** | 要件が不明確 | ヒアリング後に Issue 作成 |
| **検討中** | 選択肢を比較検討中 | Issue で選択肢を記録 |

## 自動判断フロー

```
plan 内容を受け取り
    │
    ▼
┌─────────────────────────────────┐
│ git status で変更状態を確認      │
└─────────────────┬───────────────┘
                  │
    ┌─────────────┼─────────────┐
    │             │             │
    ▼             ▼             ▼
 変更なし      変更あり      コミット済み
    │         (未コミット)       │
    │             │             │
    ▼             ▼             ▼
┌────────┐  ┌────────────┐  ┌────────┐
│仕様検討│  │ 実装中     │  │実装完了│
│フェーズ│  │フェーズ    │  │フェーズ│
└───┬────┘  └─────┬──────┘  └───┬────┘
    │             │             │
    ▼             ▼             ▼
 Issue作成   ユーザー確認    PR作成
```

## 判断チェックリスト

### Issue 作成が必要な場合

- [ ] 新しい機能を追加する
- [ ] 既存機能の動作を変更する
- [ ] 機能を削除する
- [ ] 複雑なバグ修正で仕様確認が必要
- [ ] 複数の選択肢を検討している
- [ ] ステークホルダーの承認が必要

### PR 作成のみで十分な場合

- [ ] リファクタリング (動作変更なし)
- [ ] ドキュメント更新
- [ ] 単純なバグ修正
- [ ] 依存パッケージの更新
- [ ] コードスタイルの修正

### フルワークフローが必要な場合

- [ ] 新機能で実装も支援してほしい
- [ ] Issue から PR まで一貫して管理したい
- [ ] タスク分解と進捗管理が必要

## 曖昧なケースの対処

判断に迷う場合は、以下の質問をユーザーに確認:

1. 「この変更の仕様は確定していますか?」
2. 「実装はどの程度進んでいますか?」
3. 「Issue で仕様を記録する必要がありますか?」
